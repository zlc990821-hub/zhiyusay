# 音效设计：每个动作都要"有声音"

原则：**画面上发生的每一个物理动作，都有一个听起来像它的声音**；声音和动作同一帧开始；关掉画面只听声音，也能猜到画面在干嘛。

## 1. 动作 → 音效对照表

| 画面动作 | 音效 | 写法 |
|---|---|---|
| 场景切换 / 大元素横扫入场 | `whoosh` | 切点上，gain 0.5–0.7 |
| 元素平移、卡片滑入、缩成角标 | `slide` | 动作起点 |
| 推近 / 放大 / 聚焦 | `zoom` | 动作起点 |
| 卡片弹出、标签/胶囊出现 | `pop` | 每个元素一下，pan 跟着元素左右位置 |
| 卡片翻面、规则卡展开 | `flip` | |
| 纸张、书页、文献出现 | `paper` | |
| 盖章、判定"异常" | `stamp`（+ `wrong`） | 重音，全片 ≤ 3 次 |
| 画线、描边、曲线生长、括号 | `pen` | `{ dur: 动画时长 }`，和 `g.path` 的进度同步 |
| 数字滚动、计数器 | `counter` | `{ dur: 滚动时长 }`，gain 0.2–0.35 |
| 逐个点亮、逐格出现 | `tick` | 每个一下，pan 从左到右 |
| 小球/粒子落地 | `drop` | 太多时每 2–3 个配一下，gain 0.3–0.5 |
| 金币、奖励、得分 | `coin` | |
| 正确 / 适用 ✓ | `correct` | |
| 错误 / 划掉 ✗ | `wrong`、`snap` | |
| 提示、新信息弹出 | `ding`、`bubble` | |
| 高亮、闪光、点睛 | `sparkle` | |
| 答案揭晓 | `rise` → `chime` | rise 提前约 1s |
| 标题卡 / drop / 最大反转 | `reverse`（`align:'end'`）+ `impact` + `boom` | 整片 1–2 次 |
| 片名、重要结论落定 | `thud` | |
| 拍照、定格、截图 | `shutter` | |
| 紧张、心跳、生理 | `heartbeat` | |
| 开场铺垫 | `swell` | |

## 2. 电平

`engine/audio.py` 的 `LEVEL_DB` 已把每个音效校准到相对音乐的固定电平：重击 ≈ +3 dB，点缀 ≈ 0 dB，动作 ≈ −3…−4 dB，质感 ≈ −5…−8 dB。`V.cue` 的 `gain` 只做微调（0.3–1.0）。

- 同一时刻最多 2–3 个音效叠加
- 重音（impact/boom/stamp/thud/chime）每 15–20 秒最多一次，否则就不"重"了
- 有 BGM 时自动侧链：音效响起，音乐让位 3–5 dB
- 密集重复的音效（tick/drop/pop）用 pan 左右分布，避免糊成一团

## 3. 卡点 × 音效

- 重音效尽量落在拍上：`V.cue(V.snap(t), 'impact')`
- `reverse` 类"吸进去"的音效用 `{ align: 'end' }`，让它在切点**结束**
- `V.sync()` 平移场景时，场景内的音效跟着一起移，不会错位

## 4. 写法示例

```js
// 一排 9 张卡依次弹出，每拍一张，声音从左到右
for (let i = 0; i < 9; i++) V.cue(V.B(32 + i), 'pop', { gain: 0.5, pan: -0.8 + i * 0.2 });
// 曲线 1.2 秒画完
V.cue(47.4, 'pen', { dur: 1.2, gain: 0.6 });
// 标题卡砸在 drop 上
const d = V.drops()[0];
V.cue(d, 'reverse', { dur: 1.5, align: 'end' }).cue(d, 'impact').cue(d, 'boom', 0.6);
```

## 5. 检查

`qa.py` 的"音效覆盖"：每个场景切点 ±0.5s 内必须有音效（≥ 80%）。人工再查：静音看一遍，每个元素出现时脑子里能不能"听到"它；只听声音，能不能感到节奏。
